# Project Context for AI Reviews

## What This Is
Pacific Disaster Platform - A real-time **tropical cyclone impact dashboard** for Pacific island nations (Vanuatu, Samoa, Tonga, Cook Islands).

## Tech Stack
- **Framework**: Next.js 16 (App Router) with Turbopack
- **UI**: React 19, TypeScript, Tailwind CSS
- **Maps**: MapLibre GL JS (not Mapbox)
- **Charts**: Chart.js + react-chartjs-2
- **State**: Zustand (minimal), mostly React hooks
- **Data**: Real disaster data (CSV/GeoJSON), no database

## Project-Specific Rules

### ✅ DO Flag These:
1. **Real bugs**: undefined variables, type errors, logic errors
2. **Memory leaks**: Missing cleanup in useEffect, map instance leaks
3. **Accessibility**: Missing ARIA labels on interactive maps/charts
4. **Performance**: O(n²) loops, large bundle imports, unnecessary re-renders
5. **Data handling**: Incorrect CSV parsing, GeoJSON issues
6. **Map-specific**: Layer ordering bugs, missing map.remove()

### ❌ DON'T Flag These:
1. **aria-label on canvas/chart elements** - This IS correct for accessibility
2. **Minor optimizations**: Memoizing onClick for non-frequent renders
3. **Style preferences**:ClassName complexity, button styling
4. **Generic advice**: "add more comments", "extract to function" without reason
5. **False framework claims**: Check docs before claiming something doesn't exist
6. **Over-optimization**: Stuff that has zero measurable impact

## Common Patterns (Don't Flag These)
- `any` types in data loaders (CSV has dynamic schemas)
- Dynamic imports for heavy libraries (intentional code splitting)
- MapLibre expressions (not plain JS, it's map DSL)
- Chart.js options objects (library-specific configuration)

## Terminology
- **"Event"** = District impact record (not "disaster event")
- **"Districts"** = Geographic areas affected by cyclone
- **"Exposure"** = Hazard exposure data (wind, inundation)

## Priority Issues Only
- Focus on: Bugs, security, accessibility, severe performance
- Skip: Style, micro-optimizations, architectural suggestions
